why it exists

Why Beth Studio exists

Three things got in the way of a daily terminal routine, day after day. Each one became a direct answer in the product.

  • Pain

    The terminal would hang, and sometimes it took the whole app down with it, along with everything that was open.

    Answer

    Here the interface and the terminals are separate processes. If the interface goes down, the terminals stay up.

  • Pain

    Everything needed the keyboard, in an age when the mouse and touch already exist.

    Answer

    Here everything is done by clicking. No shortcut is required.

  • Pain

    Talking is often faster than typing, but dictation tools lived outside the terminal: record, copy, paste.

    Answer

    Here dictation is part of the terminal. Record, transcribe, review and send, without leaving the program.

no lost sessions

If the interface hangs, your terminals keep running

Shells, AI agents and WSL sessions live in the host, a process separate from the interface. Closing, hanging or restarting the interface does not touch them.

  • 01

    Restart only the interface

    If the window hangs, close it and open the Studio again. The terminals come back with their history on screen, and the host never notices.

  • 02

    Update the interface without killing the host

    Under Settings > About, Recarregar interface (reload interface) applies a new interface without restarting the Studio or the host. If you update with the installer while terminals are open, it asks whether you want only the interface or the host too, and answering “No” keeps the host and the terminals. From version 0.2.1, Verificar atualização (check for updates) looks up the GitHub release and asks whether you want only the interface or the host too. The host is only touched if you confirm.

  • 03

    If the host itself goes down, it comes back

    The Studio starts another host and recreates the terminals in the same tabs and folders.

01 / architecture

How it works

  1. The host owns the terminals. bethstudio-host.exe (derived from WezTerm) holds every shell, agent and WSL session.
  2. The interface is just a layer. Studio (Go + React in WebView2) connects to the host and displays the terminals. Closing, freezing or restarting the interface does not touch them.
  3. Update without losing anything. Under Settings > About > Reload interface the new interface comes in and the host keeps running.
  4. If the host itself goes down, Studio starts another one and recreates the terminals in the same tabs and folders. What was running inside them is not recovered, only the shell, folder, title and position.

02 / voice

Talk instead of typing

Record, the text is transcribed, you review it, and only then send it. This works in Studio on Windows and on the phone page. In neither does the text press Enter by itself before you have looked at it.

Windows

In Studio on the PC

You record with the microphone, the audio is transcribed and, if you want, corrected by a language model before it is pasted into the terminal.

  1. RecordClick Speak (the button is labeled in Portuguese, “Falar”). A bar shows the sound level and warns if no sound is picked up. Recording lasts up to 10 minutes.
  2. TranscribeWhen you stop, the audio goes to the transcription provider you chose.
  3. Correct, if you wantA language model fixes recognition errors. It is off by default. If it takes too long, Studio uses the uncorrected text.
  4. ReviewSee what the correction changed and switch between the original and the corrected text.
  5. Send to the terminalThe text is pasted without pressing Enter. You confirm in the agent itself.
  • The first time, a privacy notice tells you where the audio and the text go.
  • The cost of each call is logged on this computer only, without storing audio or text. You can set a monthly limit warning.
  • The voice model and the database model are configured separately, in Settings.
  • The voice panel does not close on an outside click while it records, transcribes, corrects or shows the text for review.
Phone

In the phone WebApp

A page of its own that opens in the phone's browser. The Speak button records with a level meter.

  1. RecordTap Speak and watch the level meter.
  2. TranscribeThe audio goes up to your PC, and your PC sends it to the transcription provider you configured.
  3. Correct, if you wantThe AI correction streams into the message field itself.
  4. ReviewThe text lands in the field. Use “Voltar ao que foi transcrito” (back to the transcript) or Apagar (delete). Dictating again adds to the text.
  5. SendNothing reaches the terminal until you tap Enviar (Send), which pastes the text and presses Enter.
  • The phone never receives the voice provider's address or key.
  • It needs the bethstudio-proxy program on a server of your own. Off by default.

Screenshots of the phone page opened in a desktop browser, in a phone-sized window. (The interface is in Portuguese.)

All built in, no separate app

You pick the transcription provider and, if you want, the correction provider, under Settings > Provedores de IA (AI providers; the interface is in Portuguese). The list includes cloud and local providers, and the screen shows whether each one can transcribe, correct, or both. You do not need a separate dictation program: recording, transcribing, correcting and pasting all happen inside the Studio, in the terminal.

Teach it your vocabulary: add the terms you use most, one per line, such as project names, commands and acronyms. They go into the correction prompt and as a hint to the transcription. A ready-made technical list of languages, tools and protocols can be switched on too, and the correction prompt itself is editable.

Where the audio and the text go

The audio goes to the transcription provider you configured, and the transcribed text goes to the correction provider, if you turned correction on. With local providers, the data stays at the address you set, by default the computer itself. On the phone, the audio reaches your PC first.

Beth Studio does not keep the audio or the text: it keeps only the settings and the cost log.

03 / long sessions

For long working days

A long day in the terminal tends to follow the same script: long texts for the agent, waiting, freezes, and files going back and forth. Each item below deals with one of those, and all of them already exist in the product.

  • 01

    Talk instead of typing long texts

    Dictate with the microphone on the PC or on the phone, review, and send. Nothing is sent before you confirm.

  • 02

    A notice when the agent is waiting for you

    An amber dot shows on the tab, in the sidebar and in the tray, with an “N waiting” summary. Windows notification and sound are optional.

  • 03

    Follow along from your phone

    The list shows agents waiting for you first, with how long they have waited. Answer in large text with quick keys (1, 2, 3, arrows, Enter, Esc).

  • 04

    Persistent host

    Terminals live in a separate process. If the interface freezes, they keep running.

  • 05

    An interface you can update without killing sessions

    Reload the interface under Settings > About without restarting the host. Terminals and agents stay alive.

  • 06

    Images and files for the agent

    Paste a screenshot or a file copied in Explorer: Studio saves a copy and pastes its path. On the phone, attach an image to the message.

  • 07

    Built-in task manager

    CPU, memory, GPU and disk, plus what each terminal consumes, to tell whether the weight is in the interface or in the programs you run.

  • 08

    Terminals that come back after a crash

    If the host itself goes down, Studio starts it again and recreates the terminals in the same tabs and folders.

04 / everything it does

Features

A terminal and the tools around it, in one program. Today Beth Studio runs on Windows only.

Windows only relies on Windows featuresPC only not available on the phone or in Studio through the browser

A

Terminals and layout

Everything is done with the mouse, no config file.

  • New terminals

    cmd, PowerShell 5.1 and 7, WSL (default and named distros) and Git Bash, with the starting folder picked via Browse…
    Windows only

  • Tabs and splits

    Draggable splits (right, below, above, left), and tabs you can rename, reorder and reopen. Closing a tab does not end the terminal.

  • Sidebar views and search

    Minha organização, Como no Beth Studio, Por tipo and Por pasta (my layout, as in Beth Studio, by type, by folder). Search by title, folder, tab and, if you want, screen text.

  • All terminals

    A grid with one card per terminal and a preview of its screen, with the filters All, In tabs, No tab and Ended. It also exists on the phone page.

  • Detached terminal

    Move a terminal to its own window, even on another monitor, and drag it back to the tabs. It keeps running.
    PC only

  • End with confirmation

    Only “Encerrar terminal…” ends the process, and it asks first, warning you if an agent is waiting.

  • Repair view

    Rebuilds just that pane's screen in Studio, sends no reset to the terminal, and can be used while an agent runs.

  • History, snapshot and links

    Copy or save the full scrollback, copy or save a screen snapshot. http(s) links open in the browser; .md, .txt, .log files and images open in a preview panel.

B

Appearance

From the interface theme to each terminal's own theme.

  • Themes

    Three built-in themes, Gogh-format themes (.json files in a folder) and the color themes of your installed VS Code.

  • Font and size per terminal

    Pick theme, font and size for each terminal. A font missing on the machine is flagged in the panel.

  • Favorites and defaults

    Save theme and font combinations as favorites, and set the default theme, font and size for new terminals.

  • Right colors for programs

    The Studio theme is sent to the host, so programs that ask for the background color get it right on light themes. Text almost the color of the background is adjusted until it reads.

C

Files, notes and paste

Getting things into the terminal and writing without leaving it.

  • Paste an image or file

    Print Screen or a file copied in Explorer: Studio saves a copy and pastes its path for the agent to open (up to 8 files). In WSL, C:\… becomes /mnt/c/….
    Windows only

  • Drop a file on the terminal

    Drop up to 5 files of up to 25 MB each: images and other files become copies and the path goes to the terminal.

  • Open, edit and save

    Edit .md, .txt and .log with a formatted Markdown preview. Before overwriting a file that changed on disk, Studio asks.

  • New file and notes

    A blank editor to write right away. What you type becomes a note that saves itself, with a side list to reopen or delete.

  • File panel window

    Drag, resize, maximize, or dock to the left or right edge. Position and size are remembered.

  • Folder browser

    Inside the page, with shortcuts to the user folder, the drives and the WSL distros, and New folder.

D

Agents and voice

Knowing when the agent is waiting, and talking to it.

  • Agent waiting

    Recognizes the terminal bell, the terminal notification (OSC 9) and status variables, so it works with any agent that sends one of those signals. The notice clears when you type in the terminal or dismiss it.

  • Voice dictation

    Record, transcribe, correct if you want, review, and send to the terminal without Enter. See the section Talk instead of typing.

  • AI providers

    Several transcription and correction providers, including local ones. Keys are encrypted by Windows, or read from environment variables. Code sign-in with your account for Grok Build and Codex, for correction and the database assistant.
    Windows only

  • AI usage and cost

    Each paid call becomes a local log line, with no audio or text, with totals, a per-day chart, filtering, CSV export and a monthly limit warning.

  • Full voice test

    Runs the whole path (microphone, transcription, correction and final text) without sending anything to the terminal, showing time and cost for each step.

E

Host, WSL and tray

What keeps the terminals standing.

  • Persistent host

    One host per user owns every terminal. Closing the window, quitting the tray or updating the interface ends nothing.

  • Automatic recovery

    If the host goes down, Studio starts it again and recreates the terminals in the same tabs, folders, names and themes. A banner shows progress and anything that did not come back.

  • Update without killing terminals

    Reload the interface without restarting Studio and without touching the host.

  • WSL with smart startup

    The WSL terminal waits for the distro to respond and the folder to appear before opening, and accepts an init command per distro.
    Windows only

  • Windows tray

    Closing the window hides it in the tray. The menu has New terminal, System, Quit tray (terminals keep running) and End everything (asks first). The icon gets an amber dot when an agent is waiting.
    Windows only

  • Host life log

    Every start, stop and who asked for it is written to host-life.log, so you can tell why a terminal vanished.

F

Connections and data

SSH, serial, remote files and databases.

  • SSH and serial

    Saved SSH hosts and serial ports, with the password and key passphrase encrypted by Windows.
    PC only

  • SFTP

    A window of its own with local and remote panes and an upload and download queue.
    PC only

  • Agent login on a remote server

    If an SSH session prints a localhost link with a port, Studio opens that port on this PC through the SSH session already open.

  • Database client

    For PostgreSQL, MySQL/MariaDB, SQL Server and SQLite: object tree, SQL editor with autocomplete, saved queries and a global history, export, and an optional read-only connection.
    PC only

  • Safe data editing

    Edit cells, insert, duplicate and delete rows. Changes stay pending and highlighted until Apply, which writes everything in one transaction: if anything fails, nothing is written.

  • Database AI assistant

    Corrects SQL or answers about the open database, with a model chosen separately from the voice one. It does not run the SQL and does not send rows or passwords.

G

Phone, remote access and system

Off by default: with nothing configured, Studio only listens on the computer itself.

  • Phone WebApp

    A page of its own, installable on the home screen. A list with waiting agents first, search and type filters, a large-text chat per terminal, quick keys, image attach, voice, nine themes and the All terminals grid. It does not reach the database, SSH, SFTP, files or settings.

  • Full Studio in the browser

    The whole Studio in another computer's browser, with a password plus a code from an authenticator app. It lists open sessions and lets you end them, and the PC shows a notice while someone is connected.

  • Your server, no ports opened at home

    Both use bethstudio-proxy, a Linux program that runs on a server of your own. The PC dials out and reconnects if it drops.

  • System monitor

    CPU, memory, GPU and disk, plus what Studio, each terminal and the WSL distros use, including the WSL2 VM's memory.
    Windows only

05 / real use

Built for heavy use

The author uses Beth Studio every day with about 35 terminals open at the same time.

That means WSL2 and PowerShell sessions, several AI agents and long builds. In the author's experience, typing stays smooth in that setup, and the built-in monitor showed that the bottleneck was not WSL2.

This is real use of the project, not a performance test: there are no published measurements and no comparison with other products.

06 / install

Download and install

From the repository's Releases page. Requires Windows 10 or 11.

BethStudio-Setup.exe

Single-file installer. Recommended.

BethStudio-<version>-windows-x64.zip

Portable version: unzip it and open bethstudio-web.exe.

Open the Releases page

  1. Download BethStudio-Setup.exe and check the file against SHA256SUMS.txt.
  2. Run it, pick a folder and click Install (the button label in the installer is in Portuguese).
  3. Open Studio from the shortcut or from the installer's open button.

The install is portable: no Windows registry entries and no hidden folders. Updating while the host is running does not take down your terminals.

Linux and macOS: planned

Today Beth Studio runs on Windows only. There are plans to port it to Linux and macOS, but with no date and no commitment to deliver.
