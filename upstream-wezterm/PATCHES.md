# Upstream Patches

This directory tracks **local modifications** to files in `upstream-wezterm/`
that are required to make the vendored snapshot build with our toolchain
or to integrate with the BethTerm delta.

**The default rule** in `docs/PROJECT_LAYOUT.md` is "upstream is read-only."
This file is the **explicit exception log**: every patch we apply must be
documented here with a rationale, the exact diff, and the revert procedure.

## Format

Each patch is a separate file: `NNNN-short-name.md`, where `NNNN` is a
zero-padded sequence number assigned in order of application.

## Applying patches from a fresh upstream clone

When the vendored snapshot is bumped (see `docs/HACKING.md §10`), re-apply
the active patches. The order is:

1. `0001` and `0004` (workspace wiring) — always first.
2. `0002` (chrono clock) — if `mux` still fails with `Utc::now` not found.
3. `0003` (wezterm main) — only if we still want the binary to call our install.

## Reverting a patch

Each patch entry has a "Revert" section. Reverting means:

1. Edit the upstream file back to its original content.
2. Delete the corresponding `NNNN-*.md` entry from this file.
3. Commit with message `revert: patch NNNN <name>`.

## Why not use git apply?

The vendored snapshot is a **plain clone with its own `.git/`**, not a
submodule. `git apply` from this directory would mutate the upstream
history. We apply patches manually so the upstream `.git/` stays clean
and a `git checkout` on the upstream side can rebase cleanly.
